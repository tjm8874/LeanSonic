# Speculative target parity after EOS

On the RTX PRO 5000 72 GB at main `49dade3`, the ordinary and K=1 speculative engines produced the same first 65 tokens, including EOS (248044), on the [19-token English prompt](prompt.ids). With empty stop IDs and 128 tokens requested, at zero-based output index 80 greedy returned 271 and speculative returned 248045. Four cycles reproduced the same mismatch. Use [the fixed greedy history](greedy.ids) to compare scores on the same inputs after the first disagreement.

The greedy prompt path uses batches of up to 64 target tokens, while the original speculative prompt path uses batches of up to eight. Changing only prompt grouping was sufficient to reproduce the original flip, even with scalar decoding thereafter. Making both paths use ordinary prefill at experimental commit `a0feb50` still produced the mismatch at K=1 and K=2. This patch is not proposed for release as a parity fix. All other three held-out prompts and additional prompts of length 1, 8, 9, 64 and 65 had identical greedy IDs for 128 output positions at both K values in these runs.

With the same ordinary prefill in all cases, running only the first generated token through one-row verification and the rest through scalar decode also reproduced the mismatch (logits 19.162590 for 271 and 19.403519 for 248045). Using verification only at the final decision gave 19.760983 and 19.504147, matching the scalar ordering. Small earlier differences can change a later decision under fixed history.

A graph-disabled trace on clean main compared serial and B=1 verification after identical ordinary prefill. The first measured residual difference was already present after layer 0 attention at position 19 (relative L2 2.45e−7). The first different top-10 expert set appeared at absolute position 95, layer 3. Both paths selected the same first nine experts. Serial selected 217 last, verification 334. The post-MoE residual difference there rose to 0.02869 relative L2. At positions 95, 96, 97 and 98 the selected sets differed in 10, 16, 22 and 27 layers respectively. Position and layer indices are zero-based. Neither run used the MTP drafter or rolled back. [Per-case differences and trace metrics](measurements.json)

## Single expert intervention

At absolute position 95, layer 3, serial routing scores were −5.1076555 for expert 217 and −5.1076565 for expert 334. Verification reversed their scores. Swapping only the tenth expert ID from 334 to 217 in the verify path, with its weight untouched, restored token 271 three positions later (19.760849 vs 19.504547). Reversing that single ID in the serial path produced token 248045 instead (19.163013 vs 19.421137). This establishes a causal routing decision for the tested prefix. Hard-coding a route would not generalize.

## Reproduce on clean main

Use a scratch checkout of `49dade3`, an sm_120a cubin compiled from that revision, the direct Engram-only Q4 model and context 256. From this benchmark directory copy the desired example into the scratch checkout's `crates/leansonic-core/examples`. Run patch scripts from the root of the scratch checkout; each assumes the original source and is applied once. For crossed scalar/verify schedules apply `logits_patch.py` and build `crossed.rs` as a release example. Pass `MODEL prompt.ids greedy.ids`. For layer tracing, apply `logits_patch.py` followed by `layers_patch.py` and run the `layers` example with an additional fresh output directory as its fourth argument. Run `score_layers.py OUTPUT_DIRECTORY` for the numeric comparison. For the single-route intervention, use a fresh checkout with `logits_patch.py` and `route_patch.py` and run the `route` example with the same three input arguments. The layer trace copies data to host and is unsuitable for performance timing.
